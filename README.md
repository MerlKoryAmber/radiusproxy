# FreeRADIUS Proxy Panel

Веб-панель управления **проксированием RADIUS** в FreeRADIUS 3.2.x. Маршрутизация
настраивается не в конфиг-файлах руками, а через UI: клиенты (NAS), целевые
серверы, пулы и **правила** (client [+ маска username] → пул, опционально с
AD-гейтом и fallback на 1-й фактор AD при аварии). Панель сама рендерит из своей
БД конфиг FreeRADIUS, проверяет его через `freeradius -XC` и применяет с
автооткатом при ошибке — админ конфиг-файлы не трогает.

FreeRADIUS 3.2 работает **внутри** контейнера панели. Ставится и обслуживается
одним установщиком и хостовым CLI `rpp` — Docker, git и всё прочее ставятся сами.

## Установка

На чистом Linux-хосте (нужен `sudo` и доступ в интернет):

```bash
curl -fsSL https://raw.githubusercontent.com/MerlKoryAmber/radiusproxy/main/scripts/install.sh | sudo bash
```

Установщик ставит Docker + compose + git, клонирует проект в `/opt/radiusproxy`,
поднимает стек и ставит хостовое CLI **`rpp`**. После установки:

- **UI панели:** `https://<адрес-хоста>` (self-signed сертификат — браузер
  предупреждает; заменить в Settings → TLS).
- **Вход** по умолчанию выключен; дефолтный админ `admin` / `admin` — сменить.
- **RADIUS:** `:1812/udp` (auth), `:1813/udp` (acct).

**Сразу после установки задать боевые секреты и пароль:**

```bash
sudo rpp secrets     # APP_ENCRYPTION_KEY / JWT_SECRET (см. «Безопасность»)
sudo rpp password    # пароль админа
```

**За корпоративным прокси** (нет прямого `docker.io`, симптом
`dial tcp registry-1.docker.io:443: i/o timeout`): установщик подхватывает прокси
из окружения или `/etc/environment` сам. Если `sudo` срезает окружение — передать
явно:

```bash
curl -fsSL https://raw.githubusercontent.com/MerlKoryAmber/radiusproxy/main/scripts/install.sh \
  | sudo DOCKER_HTTP_PROXY=http://ХОСТ:ПОРТ bash
```

Прокси используется только для загрузки образов/сборки; работающие контейнеры
ходят в LDAP/RADIUS напрямую. Отключить: `DOCKER_PROXY_SKIP=1`.

## Обслуживание — `rpp`

Всё управление хостом — через `sudo rpp` (без аргументов — интерактивное меню,
или командой):

| Команда | Что делает |
|---------|-----------|
| `rpp update` | `git pull` + пересборка стека (обновиться до свежего main) |
| `rpp update-nopull` | пересборка без pull |
| `rpp status` | путь установки, git HEAD, состояние unit/контейнеров, health |
| `rpp start` / `stop` / `restart` | управление стеком (systemd-unit) |
| `rpp logs` | логи сервисов |
| `rpp backup` | дамп БД + `.env` в `storage/backup/<метка>/` |
| `rpp restore` | восстановление БД (и опц. `.env`) из бэкапа |
| `rpp password` | сброс пароля админа |
| `rpp secrets` | задать `APP_ENCRYPTION_KEY` / `JWT_SECRET` |
| `rpp git-token` | GitHub PAT на origin (для приватного репо) |
| `rpp uninstall` | удалить контейнеры/образы, **данные сохранить** |
| `rpp uninstall-purge` | удалить всё **вместе с данными** |
| `rpp url` | адрес панели + health |

Обновление на всех клиентах — только `rpp update` (тянет свежий main и
пересобирает); при старте панель сама применяет актуальный конфиг из БД, так что
маршрутизация после пересборки восстанавливается автоматически.

## Работа в панели (разделы UI)

| Раздел | Что делает |
|--------|-----------|
| **Dashboard** | сводка: клиенты/таргеты/пулы/правила, статус FreeRADIUS, время последнего apply, TLS/вход/IP-ограничение, состояние AD-синка |
| **Clients** | клиенты (NAS): ip, shared secret, source-IP, message-authenticator |
| **Target servers** | целевые RADIUS-серверы (2FA и т.п.); тип фиксирован «auth+acct»; проверка доступности (health-check: фоновый пинг / по запросу / нет) |
| **Pools** | пулы серверов: стратегия (fail-over/…), упорядоченные члены |
| **Rules** | правила маршрутизации (сверху вниз, первое совпадение): client [+ маска username] → пул; опц. AD-гейт; опц. fallback на 1-й фактор AD при мёртвом пуле |
| **Logs** | «Decisions» (лог решений) и «Server log» (лог FreeRADIUS) |
| **Config & apply** | превью того, что панель применит к FreeRADIUS, + применение с подтверждением |
| **Import / Export** | перенос настроек через файл (миграция из Windows NPS): предпросмотр → применить |
| **Settings** | Access (вход + ограничение по IP), AD/LDAP (+тест, синк групп), RADIUS (`max_request_time`), **Mail** (SMTP для алертов + тест), TLS (замена/самоподпись сертификата), Host |
| **Guide** | пошаговое руководство на русском для неспециалистов |

Все изменения применяются к FreeRADIUS кнопкой **Config & apply → Применить**:
панель бэкапит текущие файлы, пишет новые, запускает `freeradius -XC` и
**откатывает всё при ошибке валидации** — сломанный конфиг до работающего сервера
не доходит. Reload — только после успешной проверки.

## Проверка доступности целевого сервера (health-check)

Панель фоном следит, жив ли целевой сервер, а не ждёт таймаута на каждом входе.
У таргета (Target servers) поле **проверки доступности**:

- **фоновый пинг** (`status-server`, рекоменд.) — FreeRADIUS шлёт пинги каждые
  `check interval` секунд; после нужного числа успешных подряд (`answers to
  alive`) сервер снова считается живым;
- **по запросу** (`request`) — для серверов, не отвечающих на Status-Server;
- **нет** (`none`) — не проверять (недоступность ловится только по таймауту
  реального входа).

Когда сервер помечается недоступным, включается fallback (ниже), если он задан в
правиле. Подробности — `docs/adr/0010-target-health-status-server.md`.

## Fallback на 1-й фактор AD (аварийный обход 2FA)

Если за панелью 2FA (пул = 2FA-сервер) и он **полностью недоступен**, по галке на
правиле панель на время аварии проверяет только **пароль в AD** (1-й фактор) и
впускает. Это осознанный обход 2FA; такие входы помечаются в Logs как
`pool-down-1fa`. Требует включённого AD/LDAP и передачи пароля (PAP) от NAS.
Подробности — `docs/adr/0009-pool-down-ad-fallback.md`.

## Уведомления по почте (алерт об обходе 2FA)

Settings → **Mail**: SMTP-сервер (host/port), шифрование (нет / STARTTLS / SSL),
логин/пароль (опционально — для relay без авторизации оставить пустым), адрес
отправителя и получатели (несколько через запятую). Кнопка **Send test** шлёт
пробное письмо.

Когда целевой пул помечается недоступным и включается аварийный обход 2FA, панель
отправляет письмо-предупреждение: какой пул лёг, какие правила это активируют и
для кого. Одно письмо на аварию (без спама), пока сервер не оживёт.
Подробности — `docs/adr/0011-mail-alert-pool-down-fallback.md`.

## Безопасность

- **Секреты шифруются** в БД (ключ `APP_ENCRYPTION_KEY`). В боевом **обязательно**
  сменить дефолтный ключ (`sudo rpp secrets`) — при смене ключа ранее
  зашифрованные секреты не расшифруются, поэтому делать это до ввода реальных данных.
- **Пароль админа** — сменить (`sudo rpp password`); включить вход в Settings → Access.
- **HTTPS** только (nginx 443, 80 → 301), self-signed из коробки — заменить
  сертификат в Settings → TLS.
- **Ограничение доступа по IP** (Settings → Access) с защитой от самоблокировки.
- `.env`, ключи, дампы БД в git не хранятся; бэкапы — `rpp backup`.
