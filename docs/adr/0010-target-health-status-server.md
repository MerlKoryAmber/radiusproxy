# ADR-0010 — Здоровье target-сервера фоновым status-check (не на каждом запросе)

- **Дата:** 2026-09-13 МСК
- **Статус:** Accepted

## Контекст

Fallback на 1-й фактор AD (ADR-0009) срабатывает, только когда пул помечен
**мёртвым**. При `status_check = none` (как стояло на боевых таргетах LinOTP/hmk2fa)
FreeRADIUS не проверяет сервер фоном — «мёртвость» ловится лишь по таймауту
**реального** входа: первый пользователь висит `response_window` → `zombie_period`,
получает Reject, и только потом сервер уходит в dead и включается fallback. То есть
проверка де-факто идёт «на каждом проксировании», а не заранее.

Предложение владельца: проверять доступность **периодически** (фоном), помечать
недоступным после серии неудач, возвращать в строй при успехе, а fallback на AD
включать после того, как сервер помечен недоступным.

## Решение

Использовать **штатный механизм FreeRADIUS** (§16 — не изобретать), а не свой
health-loop. У `home_server`:

- `status_check = status-server` — FR сам шлёт Status-Server-пинги каждые
  `check_interval` сек; после `num_answers_to_alive` успешных подряд сервер снова
  «жив». Для серверов, не отвечающих на Status-Server, — `status_check = request`.
- Критерий «недоступности» — **сетевой** (сервер не отвечает на пинги): лёг,
  выключен, сеть недоступна. Ответ-с-ошибкой (Reject при живом порте) мёртвым не
  считается — вне объёма.
- Тайминги как аналог «после N неудач»: `response_window` (ждать ответа) +
  `zombie_period` (под подозрением, прежде чем dead). «Раз в 5 минут» = большой
  `check_interval`, но для аварийного переключения медленно — дефолт 30 сек.
- Мёртвый сервер → `home_server_pool { fallback }` → `radiuspanel_fallback`
  (проверка только в AD, ADR-0009). Ожил → трафик вернулся на 2FA автоматически.

Изменения в панели (рендер `status_check` уже был; не хватало ручки возврата):

- **`num_answers_to_alive`** вынесен из хардкода `3` в поле `TargetServer`
  (`radius_config.render_home_server`), схема `ge=1,le=10`, миграция
  `ADD COLUMN IF NOT EXISTS ... DEFAULT 3` (`_migrate`).
- Дефолт `status_check` = `status-server` (был; на боевых таргетах вручную стоял
  `none` — при обновлении сменить на фоновый пинг).
- UI (`TargetServers.jsx`) — русские подписи + хинты (§21): «Проверка
  доступности» (фоновый пинг / обычным запросом / не проверять), «Интервал
  проверки», «Успешных проверок для возврата», «Ожидание ответа», «Период
  подозрения», «Интервал оживления». Поля пинга скрыты при `none`.
- `num_answers_to_alive` добавлен в portable-экспорт/импорт.

## Требования / ограничения

- 2FA-сервер должен **отвечать на Status-Server** — иначе `status_check = request`.
  **Не проверено вживую** (LinOTP/2FA на момент решения недоступны) — проверить,
  когда появятся: отвечают ли пинги, и уходит ли пул в fallback без таймаутов на
  клиенте.
- Ложное срабатывание при флапе сети → преждевременный обход 2FA; регулируется
  `zombie_period` / `num_answers_to_alive`.

## Проверка

`freeradius -XC` — OK на сгенерированном конфиге. Динамика (сервер отвечает/лёг →
alive/dead → fallback) — **TODO на живых LinOTP/hmk2fa** (см. ограничения).
