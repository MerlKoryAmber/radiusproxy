# ADR-0001 — Расширение панели: policy/ldap/логи, AD-гейт per realm, аудит в Postgres

- **Дата:** 2026-09-06 МСК
- **Статус:** Accepted
- **Контекст:** [docs/design/NOTES_proxy_policy.md](../design/NOTES_proxy_policy.md)

## Контекст

Три требования к проксированию: (1) сохранять IP инициатора; (2) проверять членство
пользователя в группе AD — **своя группа на каждый realm/рул**; (3) логи решений.
Все три — вне `proxy.conf` (policy виртуального сервера + модули `ldap`/`sql`).

## Решения

1. **Скоуп: панель генерит всё.** `radius_config.py` расширяется рендерерами:
   `proxy.conf` + `mods-enabled/ldap` + policy-сниппеты (`authorize`/`pre-proxy`/`post-proxy`)
   в `sites-enabled` + `mods-enabled/sql`. Один источник правды — data-модель панели.
   Принцип «FR-синтаксис в одном модуле» сохраняется.

2. **AD-гейт делает прокси, per realm.** Модуль `ldap` на AD (LDAPS, base_dn, bind DN +
   пароль-секрет, кэш членства с TTL). Data-модель: realm += `required_ad_group(s)`,
   `username_normalization` (`user@realm` / `DOMAIN\user` / `sAMAccountName`), `fail_mode`.
   Policy маппит realm → требуемая группа; нет членства → reject (не проксировать).

3. **Логи в Postgres панели.** Модуль `sql` FR пишет решение в таблицу `proxy_audit`;
   UI панели показывает/фильтрует. Поля: ts, NAS-IP, Packet-Src-IP, User-Name (сырой+норм),
   realm/рул, AD-группа + результат, цель прокси, ответ upstream, латентность. Секреты/пароли
   не логируются. Ретеншн — параметром.

4. **AD недоступен → fail-open** (проксировать без проверки группы).
   ⚠️ **Против §4 (fail-closed) CLAUDE.md** — выбор владельца, принят с митигациями:
   - **Кэш last-known-good членства** (TTL): при коротком сбое AD гейт работает из кэша,
     полный fail-open только когда и кэша нет.
   - **Громкий аудит:** каждый пропуск без проверки маркируется в `proxy_audit`
     (`ad_check = SKIPPED_AD_DOWN`) — не тихо. Опц. алерт.
   - `fail_mode` — параметр per realm: можно на чувствительных рулах включить fail-closed.

## Отвергнуто

- **Панель только proxy.conf + ручные шаблоны policy** — настройка в двух местах, дрейф.
- **Логи только в файлы (linelog/detail)** — для UI нужен парсер/шиппер; Postgres уже есть.
  (detail-файл можно добавить позже для полного дампа при разборе инцидентов.)
- **AD-проверку на home server** — требование прямо про гейт на входящем запросе.

## Последствия

- Секрет bind AD — шифрование + env, не в git/логи. Нужен механизм шифрования настроек.
- LDAP-запрос на пакет → обязателен кэш членства (нагрузка на AD, латентность).
- Панель управляет несколькими FR-файлами → apply/rollback (§5) должен покрывать все,
  валидация `freeradius -XC` — на полном наборе, не только proxy.conf.
- Порядок обработки и генерируемые сниппеты — в NOTES_proxy_policy.md.
