# ADR-0011 — SMTP-настройки + email-алерт при активации обхода 2FA

- **Дата:** 2026-09-13 МСК
- **Статус:** Accepted

## Контекст

Обход 2FA (ADR-0009: при мёртвом пуле — вход по одному паролю AD) — событие
безопасности. Оператор должен узнавать о нём **сразу**, а не постфактум из логов.
Нужны: настройки почтового сервера в панели и письмо-предупреждение при
включении режима — куда, что включилось, для кого, почему.

## Решение

- **`MailSettings`** (singleton id=1): `enabled`, `host`, `port` (дефолт 25),
  `security` (`none`/`starttls`/`ssl`, дефолт none — внутр. relay), `username`,
  `password` (EncryptedStr, write-only в API), `from_addr`, `to_addrs`
  (несколько через запятую). UI — Settings → вкладка **«Почта»** (§21: русские
  подписи+хинты) + кнопка «Отправить тест».
- **Триггер = активация режима**, не каждый вход (выбор владельца). Момент «пул
  лёг» знает FreeRADIUS, не панель, → бэкенд узнаёт из radius.log.
- **`mailer.py`**:
  - `send_mail(cfg, subject, body, to_override)` — stdlib `smtplib`
    (none/STARTTLS/SSL, опц. auth). Ошибку пробрасывает (тест-эндпоинт покажет).
  - `pool_down_watch()` — фоновый loop (рядом с `_group_sync_loop` в lifespan):
    тейлит radius.log, ловит `Home server pool <POOL> failing over to fallback
    radiuspanel_fallback`. По имени пула находит enabled-правила с
    `pool_down_fallback` → клиенты/маски username. Шлёт одно письмо на аварию;
    повторно — только после `Marking home server ... alive again` (дедуп по
    пулу). Старт с текущего конца лога (рестарт не шлёт старые аварии). Ошибки
    loop не убивают.
- **API** (`/api/system/mail`): GET (Out с `has_password`, без секрета), PUT
  (write-only пароль: пусто = не менять), POST `/mail/test`.
- Новая таблица создаётся `create_all` — миграция не нужна.

## Требования / ограничения

- Письмо шлётся по логовому маркеру — если формат строки FR изменится, детектор
  надо обновить (`_FALLOVER` в `mailer.py`).
- Дедуп в памяти процесса: рестарт бэкенда во время аварии → возможно повторное
  письмо при следующем событии fallover.
- Порог «пул лёг» определяется настройками таргета (ADR-0010:
  `status_check`/`zombie_period`) — при `status_check=none` fallover наступит
  только по таймауту реального входа.

## Проверка

`freeradius -XC` не затрагивается (mail — вне конфига FR). Отправка проверяется
кнопкой «Отправить тест» и по факту аварии пула. Live-проверка на реальном SMTP
и реальном падении пула — **TODO** (SMTP-relay/LinOTP на момент правки
недоступны).
